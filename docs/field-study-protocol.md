# 真实场景验收与采集审计

本文件用于补齐公开数据无法证明的“夜间主动近红外”和“实景强逆光”条件。公开近红外库并不自动等于夜间，受控侧/背侧光也不自动等于明亮背景的强逆光。

## 实际需要的材料

- 至少 10 名已知人员，建议 20 人以上；另设互斥的未知校准人员与未知测试人员。
- 图库、校准、测试分别采集，使用不同会话编号。同一视频或连拍的邻近帧不能拆到不同划分。
- 正常、低照度、强逆光、夜间主动近红外分别记录设备、波段/补光、测光值（可用时）、摄像机/人脸/光源位置、日期与会话。
- 红外需真实近红外相机或去除 IR-cut 的设备及近红外补光。RGB 变灰、人工压暗、热红外图不能替代。
- 背景亮、脸部暗不应只凭软件亮度阈值认定强逆光。保留照明布局记录和采集说明，确认主要光源位于人脸背后。
- 人脸框由人工或独立标注流程完成；不要使用待测检测器的预测框作为它自身的真实标注。

## 采集数量

每个需要判定的场景至少 100 次已知身份查询及 10 名已知人员；建议跨日期重复采集。样本数量达到门槛仍不表示达标，必须计算正确数、分母、未知误接受和区间。

综合目标要求正常、低照度、强逆光三场景都有真实查询，按逐样本计数汇总。红外目标单独评价。默认未知 FAR 校准目标为 1%，小规模未知数据的观测 0% 也不能保证总体 FAR≤1%；应同时看区间和未知身份数量。

## 使用模板

复制 `experiments/configs/field-study-template.json` 到实际图片所在的目录。保持它的 source/license 与证据描述可追溯；仅在实际采集记录支持时将 night_confirmed、active_illumination、backlight_confirmed 等设为 true。模板的 images 为空，不能生成任何性能结果。

每个 images 元素格式：

```json
{
  "file": "images/subject01-test-session03.png",
  "role": "test",
  "scene": "infrared",
  "capture_id": "night-test-20261020-session03",
  "faces": [
    {"bbox": [80, 60, 260, 300], "person_id": 1, "subject": "subject01"}
  ]
}
```

role 为 gallery、calibration、test。person_id 对应已注册身份；未知人员设 null，subject 保持同一人员的匿名标识。框坐标对应 EXIF 纠正后的图片。上面只是格式示例，不是已采集照片或真实框。

## 自动审计与导出

```bash
.venv/bin/python scripts/audit_field_data.py /path/to/collection.json \
  --output work/my-field-study
# 标签、会话、文件和证据检查通过后可导出导入包
.venv/bin/python scripts/audit_field_data.py /path/to/collection.json \
  --output work/my-field-study --export
```

输出 field-audit.json，包括错误、各场景覆盖缺口和 ready_for_target_assessment。空数据、重复像素、跨划分会话、未知身份重叠、缺场景证据不会被标成验收就绪。脚本不声称能通过像素证明硬件与实际环境，场景记录仍需实验负责人核实。

导出的 calibration/test ZIP 同时按最多 500 图、90 MB 无损图片总量和 1 MB 标注预算分包，为系统 100 MB 压缩包 / 256 MB 解压 / 2 MB 清单限制留出余量。单图无损 PNG 超过 12 MB 会明确提示先处理图片并同步修正人工标注。样本不足但没有标签/泄漏错误时可导出探索性实验，报告仍标为缺口未补齐。大于单任务上限时按固定顺序分包，跨包统计必须合并逐样本计数，不能平均各包百分比；冻结阈值后才运行测试。

先完成身份注册，核对图库编号及采集会话；导入校准集、运行五组方法、冻结阈值，再运行测试。对多包校准应使用同一份完整离线校准协议，不能根据每包测试效果重新选阈值。

## 判定规则

系统现在同时检查真实采集、独立会话、真实校准集冻结阈值、场景证据、人员数和查询数。点估计达到目标但 95% 区间下限不足时会单独标示。公开受控基准会保留实测计数，同时明确其不具备的现场证据。
