# Codex 开发任务：复杂光照条件下人脸检测增强算法及系统实现

你是一名具有计算机视觉、深度学习、Python 后端和 Vue 前端开发经验的高级全栈工程师。

请在当前工作目录中，独立完成一个本科实训项目：

**项目名称：复杂光照条件下人脸检测增强算法及系统实现**

本项目必须采用 B/S（Browser/Server）架构，实现可运行、可测试、可展示的人脸检测增强与身份确认系统。

你不仅需要编写代码，还需要完成项目架构设计、算法模块实现、系统集成、实验评估、自动化测试与项目文档。

## 一、项目背景和研究目标

针对强光、逆光、夜间低照度等复杂光照场景，研究并实现图像质量增强、自适应曝光补偿和光照归一化技术，提高不同光照条件下的人脸检测效果及身份确认准确率。

项目重点是通过图像预处理与成熟的人脸识别模型相结合，改善复杂光照环境中的识别性能。

优先采用已有开源算法、预训练权重和成熟技术，避免不必要地从零训练大型深度学习模型。

### 预期考核指标

1. 红外补光夜间场景：人员自动身份确认率不低于 95%。
2. 强逆光场景：人员自动身份确认率不低于 90%。
3. 正常光照、夜间低照度和逆光场景均覆盖的综合测试集：人员自动身份确认率不低于 95%。

这些是项目目标，不是已经达到的实验结果。

必须通过真实测试数据验证，严禁伪造、硬编码或虚构实验指标。

首先区分人脸检测准确率、人脸识别准确率和人员身份确认率，给出清晰的指标定义、阈值选择方法及测试协议。

若公开数据不足以直接验证上述指标，必须明确记录验证范围、数据限制以及尚未达成的要求。

## 三、核心算法模块

### 1. 图像光照分析

实现图像质量分析模块，对输入人脸图像进行亮度和质量评估。

至少包含：

- 图像平均亮度分析
- 亮度直方图分析
- 过曝与欠曝区域比例计算
- 图像对比度评估
- 光照均匀性分析
- 图像清晰度评估

设计基于实际统计特征的光照场景判断模块。

能够对正常光照、低照度、强逆光、局部过曝等场景进行初步分类。

不要求复杂的神经网络光照分类器，可以优先采用具有可解释性的传统图像处理方法。

### 2. 图像质量增强

实现并封装以下图像增强算法：

- Gamma 校正
- CLAHE 自适应直方图均衡化
- Retinex（优先实现 Single Scale Retinex 或 Multi Scale Retinex）
- 基于亮度统计的曝光补偿
- 光照归一化处理

要求所有算法均可单独调用。

每个算法应具有独立的参数配置与统一的输入输出接口。

必须保证输出图像格式正确，避免数值溢出、颜色失真和异常图像导致的程序崩溃。

### 3. 自适应光照增强策略

设计一个自动图像增强模块。

根据输入图像的亮度分布、对比度和光照不均匀程度，自动选择合适的增强方法及参数。

建议策略：

- 正常光照：不增强或进行轻量处理
- 夜间低照度：Gamma 校正与 CLAHE
- 强逆光：局部对比度增强及曝光补偿
- 光照不均匀：Retinex 或组合增强
- 过曝图像：优先进行保守处理，避免进一步丢失细节

上述策略只是初始设计，应通过真实实验决定最终规则。

需要实现增强开关，以便进行增强前后的消融实验。

不要假设图像增强必然提升人脸识别效果，应允许根据实验结果调整或关闭某个增强分支。

### 4. 人脸检测

使用成熟的开源人脸检测模型，例如 InsightFace 集成的人脸检测器。

功能包括：

- 单人脸检测
- 多人脸检测
- 人脸边界框展示
- 人脸关键点定位
- 检测置信度输出
- 人脸裁剪与对齐

支持对比：

1. 原始图像的人脸检测结果
2. 增强图像的人脸检测结果

展示检测数量、置信度和处理耗时。

### 5. 人脸识别与身份确认

使用 InsightFace 的预训练人脸特征提取模型完成身份识别功能。

实现：

- 人脸特征向量提取
- 人脸特征归一化
- 余弦相似度计算
- 身份注册
- 身份库管理
- 1:1 身份验证
- 1 身份检索
- 未知身份拒识
- 相似度阈值配置

身份注册时支持上传多张参考照片，并记录每张照片的特征向量和质量评估结果。

识别时返回匹配身份、相似度、阈值、是否确认成功及必要的诊断信息。

不得将无匹配人脸强行归类到已注册身份。

对红外图像，应明确判断所选模型是否支持可见光与红外跨模态识别；不能将普通 RGB 模型在红外图像上的效果视为已有保障。

### 6. 算法效果对比与消融实验

至少支持以下实验组：

- 原始图像，不增强
- Gamma 增强
- CLAHE 增强
- Retinex 增强
- 自适应增强策略

在相同人脸检测模型、识别模型、身份库和测试数据条件下进行公平对比。

实验指标应至少包含：

- 人脸检测召回率
- 人脸检测精确率
- 身份确认成功率
- 未知身份误接受率
- 平均处理耗时
- 各场景下的分组统计结果

测试时不得使用测试集标签来选择增强方法或调整识别阈值。

整体采用现代化后台管理系统设计，中文 UI，布局清晰、美观且适合本科实训答辩展示。

- 最近实验结果概览

统计数据必须来自真实数据库，不能使用虚假的固定统计数值。

### 页面二：图像增强实验室

支持上传 JPG、PNG 等图片。

功能包括：

- 原始图像预览
- 自动光照分析
- 手动选择增强算法
- 自动增强模式
- 参数调节
- 增强前后对比
- 亮度直方图展示

上传图像后展示：

- 增强后图像检测结果
- 人脸框与关键点
- 检测置信度
- 检测数量
- 两种模式的耗时和结果比较

### 页面四：身份注册与身份库管理

支持：

- 添加人员身份
- 上传多张人脸照片

### 页面五：身份确认

实现身份验证与识别。

支持两种模式：

1. 1:1 身份验证：上传图片并指定目标身份。
2. 1 身份检索：上传图片并在身份库中查找候选身份。

展示：

- 原始图片
- 图像增强结果
- 人脸检测结果
- 匹配人员
- 相似度分数
- 决策阈值
- 身份确认结果
- 识别耗时

支持手动开启或关闭图像增强，以展示复杂光照增强带来的实际效果。

### 页面六：实验评估

支持批量导入具有真实身份标签及场景标签的数据集。

功能包括：

- 数据集管理
- 测试任务创建
- 批量评估
- 原始图像与增强图像对比
- 各算法指标比较
- 正常光照、低照度、逆光、红外补光场景统计
- ECharts 可视化图表
- 导出 CSV 实验结果

各项指标必须根据真实预测结果计算。

如果缺少某场景的真实测试数据，应标记为“未评估”，不得显示为已达标。

## 五、数据库设计

采用 SQLite 实现轻量级数据存储。

至少设计以下数据表：

1. Person：人员身份信息
2. FaceSample：注册人脸样本与特征索引
3. RecognitionRecord：身份确认记录
4. Experiment：实验任务信息
5. ExperimentResult：实验结果信息
6. Dataset：数据集元信息

要求数据库结构清晰，使用 SQLAlchemy ORM 管理。

处理涉及人脸信息的文件和特征数据时，应限制文件访问范围，避免不必要地公开原始图像和特征向量。

提供删除人员信息及关联人脸样本的功能。

本项目定位为本地教学与研究演示系统，不应将身份识别结果作为真实场景中唯一的身份认证依据。

如最终指标未达到要求，应客观记录，并分析模型、数据集、阈值与图像增强策略的影响，继续尝试合理优化。
