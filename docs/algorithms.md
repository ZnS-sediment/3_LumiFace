# 算法说明

## 光照分析

输入固定为 `uint8 H×W×3 BGR`。灰度采用 OpenCV BGR2GRAY。

- 平均亮度：μ = ΣY / N，范围 0–255。
- 直方图：256 个灰度桶，计数总和等于像素数。
- 欠曝比例：Y < 30 的像素比例；过曝比例：Y > 240。
- 对比度：灰度标准差，不等同于局部人脸可识别性。
- 光照不均匀度：4×4 网格的块均值标准差 / max(全局均值, 1)。
- 清晰度：Laplacian(Y) 方差；噪声也可能增大该值，因此不将其独立视为质量保证。
- 逆光线索：图像中心一半区域均值与外圈均值的差。

按顺序判断：外圈比中心亮 >45 且中心均值 <110 为逆光；否则均值 <75 或欠曝 >55% 为低照度；否则过曝 >18% 为过曝；否则不均匀度 >0.4 为不均匀；其余正常。此为可解释初始规则，受构图影响，不是已训练或已验证的场景分类器，不能从灰度自动识别红外模态。

## 网页算法选择

网页统一提供 Gamma 校正（低照度）、CLAHE（逆光）、Retinex（光照不均）三种增强算法，默认 Gamma。算法旁展示处理侧重；侧重不是场景性能保证。CLAHE 只增强局部对比度，不能恢复饱和丢失的信息；Retinex 估计平滑光照，对极端阴影也可能放大噪声。

网页新建实验默认使用 original/gamma/clahe/retinex，其中 original 是不增强对照组。自适应、曝光补偿、归一化不再作为网页新任务选项；以下实现和 API 兼容仍保留，历史结果按原方法显示，不改写已完成研究证据。

## 按图片自动调参

网页只保留三种算法选择，增强、检测、身份确认和新建多图测试均逐图调参，无需手动滑块。算法本身仍由用户选择，不自动切换。分析图最长边至多 512px，使用图片统计量，不读取真实身份、图库或相似度：

- Gamma：根据完整灰度直方图二分求解约 115 的期望亮度，γ 限制在 [0.35,1.8]；近乎全黑/全白的饱和图用 γ=1。彩色通道和取整会导致实际亮度与目标略有差异。
- CLAHE：结合 10/90 分位明暗范围、4×4 块均值变化和中值滤波残差估计噪声，自动计算对比度限制，范围 [1.1,3.8]；噪声越高，增强调节越保守。
- Retinex：用原图短边尺寸与明暗不均程度确定 σ∈[3,100]；结合暗部比例、不均程度和噪声确定 strength∈[0.1,0.75]。

自动规则版本为 `image-statistics-v1`。图像增强结果显示实际参数；多图实验把逐张实际参数冻结到结果中，回放优先使用冻结值。它们是有界启发式规则，不保证每张图的识别相似度提升。

API 可通过 `auto_parameters=false` 继续使用显式参数，以复现历史结果。普通研究实验 API 默认 false；网页多图测试默认 true。历史数据和已完成实验不改写。

## 独立增强算法

| 方法 | 实现 | 参数与保护 |
|---|---|---|
| Gamma | Y=(X/255)^γ×255，对 RGB/BGR 通道采用相同 LUT | γ∈[0.15,4]，小于 1 提亮，大于 1 压暗 |
| CLAHE | Lab 的 L 通道局部均衡，8×8 网格 | clipLimit∈[0.1,8]；保留 a/b 通道 |
| SSR Retinex | log(Y+1)−log(Gσ*(Y+1))，1/99 分位线性映射，再与原亮度混合 | σ∈[3,100]；strength∈[0,1]；常量图直接返回 |
| 曝光补偿 | gain=clip(target/max(meanY,1),0.5,3)，按强度混合增益 | target∈[40,190]，限制高增益 |
| 光照归一化 | 亮度 2/98 分位映射到 [15,235]，与原亮度混合 | 常量/低动态范围返回原图 |
| Original | 输入副本 | 消融基线、关闭增强 |

Retinex 在最大边 512 的亮度图估计平滑光照，再插值回原尺寸，避免大图巨核的耗时失控；对数采用 +1 防零，输出截断到 0–255 后转 uint8。SSR、曝光、归一化保持 YCrCb 色度分量。色彩空间转换和截断仍可能影响颜色；不宣称绝对无色差。

统一入口：`enhance(image, EnhanceOptions(...)) -> (output, steps)`。独立函数 `gamma/clahe/retinex/exposure/normalize` 可以直接调用，输入不会被原地修改。

## 历史自适应方法

- 正常：原样保留。
- 低照度：按全局均值计算 Gamma，限制 [0.35,0.9]，随后 CLAHE clip=1.6。
- 逆光：CLAHE clip=2 后保守曝光 target=110、strength=.35。
- 光照不均匀：SSR sigma=30、strength=.45。
- 过曝：Gamma=1.15；饱和像素的信息无法恢复。

上述历史像素变换保持兼容；当前识别流水线版本为 `ALGORITHM_VERSION=lumiface-1.4`。实验运行不根据测试标签或最终分数修改策略。未来优化需先在开发/校准数据上决定分支开关，然后新版本冻结后重新测试。固定参数模式保留 `EnhanceOptions` 默认值；新网页任务使用上述逐图自动参数规则，配置和逐图参数都写入实验记录。

## 检测与对齐

SCRFD 输出框、五点和检测置信度。检测页、身份确认支持多张人脸；注册参考照片仍严格要求恰一张人脸。五点对齐使用 InsightFace 的相似变换 `norm_crop`，得到 112×112 人脸。检测置信度不是身份相似度，也不是概率校准后的人脸真实性。

## 特征与身份决策

ArcFace 每张参考脸提取 512 维特征：u=f/||f||₂。每人模板为各样本归一化特征平均后再次 L2 归一化，原始逐样本特征保留以支持质量检查。相似度 s=uᵀv ∈[-1,1]。

1:1：仅与指定身份模板比较；1:N：全图库取最高相似度。当 s≥τ 才返回确认身份；否则 person_id=null、name=未知身份。候选列表只是诊断信息，不强制归类。

默认 τ=.45 是演示初值。图库规模、成像模态、年龄变化、图像质量都影响分数分布；正式测试必须在独立校准集选阈值。模型指纹与注册模板绑定，不混用不同模型的特征。对本项目已知的旧模型，服务从注册原图生成匹配当前模型的新特征；未知来源的模型指纹仍拒绝复用。

## 原图与增强特征融合

网页身份确认和新建自动参数实验使用 `face-local-v4`。原图和增强图分别检测人脸，原图五点用于固定对齐，增强图中与已有框 IoU <0.3 的新检测脸另外保留。

- Gamma 保持 `unit(0.7 × 原图特征 + 0.3 × 同位置增强特征)`。
- CLAHE 在对齐的 112×112 人脸上自动调整光照，分别提取局部增强和水平镜像特征；融合权重为原图 0.7、局部增强 0.15、镜像 0.15。
- Retinex 保持全图自适应光照校正，使用原图五点提取同位置特征，融合权重调整为原图 0.5、增强图 0.5。开发照片上比较 0.3/0.5/0.7/1.0 四个增强权重，在不降低正确数、不增加未知误接受的候选中选择真实身份平均余弦分数最高的一项。

每个特征先归一化，融合后再次归一化。参数只根据图像计算，推理不读取真实身份或最终正确率。原图对照、参考特征与所有方法的判定阈值不变。CLAHE 采用局部人脸统计，减少背景和灰色边框对自动参数的影响；镜像增加特征视角，也增加一次特征提取开销。Retinex 和 Gamma 没有增加特征提取次数，不声称所有方法运行速度更快。

这是一条融合识别流水线，不能把提升归因于像素增强算子单独作用。增强页和下载图片保持原有像素处理。新实验冻结 `recognition_policy`、各方法的 `recognition_parameters`、模型指纹和算法版本；`processed-v1`、`aligned-fusion-v2/v3` 历史路径保留，历史结果不重写。选择参数使用旧包身份的额外照片 6–8，不使用新 280 人测试包查询标签；开发与验证身份分开。
多脸图片对每张脸独立取图库最高身份并过阈值，只返回已确认身份的集合；未过阈值的候选不计入。网页新测试使用 image_identity_presence：单脸必须精确命中真实身份；多脸只要任一已确认 person_id 等于真实 person_id，整张图片正确，分母仍为一张。未知标签图片只要任一脸被接受，就算一次误接受。单脸不使用姓名子串匹配，多脸也按编号精确比较。

该协议只有图片级标签，没有其他脸的独立框标注，定位计数仅表示图片内存在人脸，不能解释为逐脸检测精确率。IoU、眼点和历史 single_face_presence 协议不变；新协议不用于单脸阈值校准。

## 红外限制

当前模型为通用可见光模型。系统能够解码红外灰度图并转三通道执行同样流水线，但这不等同于具备跨模态识别保障。红外标签来自真实采集元信息，不能由低亮度或人工 Gamma 变暗替代。需分别报告 RGB→RGB、IR→IR、RGB→IR 的图库/查询模态；当前 UI 保留来源说明，模态具体协议须写入清单 source 和实验报告。


### 识别计算复用（1.2）

`aligned-fusion-v3` 保持 v2 的检测框、同位置融合权重和阈值判定规则。增强图仍扫描全部人脸，但只为原图框及去重后的新增脸提取一次所需特征，不再提取随后丢弃的重复检测脸特征。批量比较时，每张图的原始检测与特征只计算一次，在该图各方法之间复用；不跨图片、身份库或实验缓存。

平均耗时按“完整原图推理成本 + 当前方法其余处理成本”统计，包括自动参数、增强、增强图检测、必要特征和匹配；缓存不会让原图成本消失。各方法平均耗时之和不等于批量任务总等待时间，因为后者实际共享原图计算。历史 `aligned-fusion-v2` 与 `processed-v1` 配置继续按原路径运行。

这次优化消除重复计算，未更改识别阈值、融合权重和正确性定义，不声称提升正确率。原图已接近 99% 的这组模拟数据提升空间很小；提亮不保证增加身份特征的区分度。验证命令：`OPENBLAS_NUM_THREADS=1 OMP_NUM_THREADS=1 .venv/bin/python scripts/benchmark_recognition_latency.py`，依赖已有 `work/quality-v2` 实际模型特征缓存和下载包，产出 `work/recognition-latency-v3.json`。缓存回放验证等价性；真实推理抽样单独测量耗时。


### 识别模型升级（1.3）

默认识别头由 `w600k_r50` 更换为官方 `antelopev2/glintr100.onnx`（ResNet100@Glint360K），SCRFD 检测器、五点对齐、原图/增强图 0.7/0.3 融合和相似度阈值 0.45 均不变。改进来自身份特征模型，不应归因于像素增强算子单独提升。新实验保存识别头名称、实际权重指纹及算法版本。

旧身份的原始 `face_samples.embedding` 与模型指纹不覆盖；`face_encodings` 按样本和新模型指纹保存派生特征。只对已知兼容模型执行更新，读取注册原图前校验摘要并要求恰有一张人脸，整批成功后提交。启动时预先建立图库，后续识别直接读取缓存。删除身份时，派生特征随参考样本一起清除。

旧模型通过启动前设置 `LUMIFACE_RECOGNIZER=w600k_r50` 复现；默认 `glintr100`。不同模型的校准结果不能互用，历史记录不会重算。对比脚本为 `scripts/benchmark_recognition_backbone.py`：依赖原始 LFW 下载包及本机 `work/quality-v2` 固定检测缓存，重算新模型参考/查询特征，保持检测框与数据划分一致。需要重新全量计算时指定新的 `--output-dir`；当前完整结果在 `work/accuracy-v4`。

### 默认判定参数（2026-11-04）

模型对比与既有研究的 0.45 设置保留在历史结果中。当前网页隐藏阈值，新任务的 glintr100 默认值由独立开发身份与未知身份开发划分选择，冻结为 0.435；验证身份与原 120 人包不用于选值。使用已知正确识别率与未知拒绝率的均衡准确率，取最优连续区间中点。原模型回放仍默认 0.45。校准条件、有限样本误接受及留出验证结果见 `default-threshold-calibration.json`，不能把默认值称为所有图库的全局最优。
