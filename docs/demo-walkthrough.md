# LumiFace 现场演示操作稿

建议时长：6–8 分钟。按当前已导入的 40 个 AT&T 匿名身份准备。

## 演示前准备

1. WSL 中运行 `cd /home/zns/3_LumiFace`，再运行 `bash scripts/start.sh`。已在运行时直接打开 http://localhost:5173。
2. 系统概览点击“加载模型”，确认“已加载”。当前演示库已有 40 人，无需反复导入。
3. 在“身份库管理 → 批量导入身份”点击“下载 AT&T 演示数据包（40 人）”，下载到 Windows 后解压。后续通过 Windows 本地文件选择器选图，不依赖 WSL 共享路径。
4. 找到解压目录中的 `gallery` 和 `query`。例如解压到 `C:\LumiFace-demo` 后，查询图可能位于 `C:\LumiFace-demo\att_faces_demo\query\ATT_s01\04.png`；以实际解压结构为准。
5. 现场只用 `gallery` 注册、`query` 查询。准备 `query/ATT_s01/04.png` 作为主要查询图；另有真实暗光或逆光照片时，用于增强页面。
6. 提前按下表排练一遍。身份列表编号从 1 连续显示，搜索或删除后重新排列。

## 操作顺序与讲解

| 顺序 | 具体操作 | 可以这样讲 |
|---|---|---|
| 1，30 秒 | 系统概览展示人数、检测记录及模型“已加载” | “这是 LumiFace，包含图像增强、人脸检测、身份库管理、身份确认和实验评估。” |
| 2，1 分钟 | 图像增强实验室上传暗光图，先运行自适应，再切换 Gamma 或 CLAHE，观察原图、结果图、直方图和耗时 | “系统提供多种增强方法，可以对比亮度与细节变化，并下载处理结果。” |
| 3，1 分钟 | 人脸检测上传查询图，点击“运行双路检测”，展示人脸框、五点关键点和对齐裁剪 | “原图和增强图使用同一检测模型，结果可直接对照。” |
| 4，1 分钟 | 身份库管理展示从 1 开始的编号、搜索 ATT_s01、点击“查看”展示 3 张参考照片；清空搜索后打开批量导入 | “每个人可以注册多张参考照片。根目录下每人一个子目录，选择目录后直接导入，无需填写数据批次。” |
| 5，2 分钟 | 身份确认先关闭“图像增强”，保持阈值 0.45，使用下方三个例子 | “1:N 在图库中检索，1:1 对指定人员验证，相似度不足时拒绝确认。” |
| 6，1–2 分钟 | 实验评估顶部选择 query 查询目录，核对自动匹配身份，勾选不增强和 Gamma，点击“开始多图测试”，展示正确数/总数、逐张结果与 CSV；再次测试展示新记录 | “可以一次测试多张照片。正确率包含漏检、拒识和认错；每次测试自动更新当前评估，历史结果保留。” |
| 7，按需 | 页面下方切换 CBSR、Yale B 报告，查看区间、适用范围并下载真实逐样本 CSV | “公开研究结果与本轮网页测试分别记录，场景和数据范围需要核对。” |

AT&T 图像可用于展示增强按钮、图像对比和统计流程；它不能替代真实暗光或逆光照片来证明场景效果。正常图使用自适应算法时可能保持原图，以实际结果说明。

### 身份确认的三个具体例子

统一使用 `query/ATT_s01/04.png`，关闭图像增强，阈值保持 0.45。

1. 选择“1:N 身份检索”，上传该图，点击“开始身份确认”。观察候选身份、分数和是否确认为 ATT_s01。
2. 切换“1:1 身份验证”，目标身份选 ATT_s01，再点击“开始身份确认”，展示同一人的匹配结果。
3. 目标身份改为 ATT_s02，仍使用这张 ATT_s01 的查询图，再执行一次，展示指定身份不匹配。这个例子属于对指定人员验证失败，不能称作“图库外未知人员测试”。

按当前 40 人图库进行只读离线排练，以上查询的 1:N 首名为 ATT_s01，相似度约 0.726；指定 ATT_s02 时约 0.190，低于 0.45。排练未向业务库新增身份或识别记录，这些单图结果不构成准确率评测。

现场不要为了得到成功结果临时调整阈值并据此宣称性能达标。0.45 是演示默认值，正式评测需要独立校准。

### 批量导入与错误提示怎么演示

- 空目录状态点击“开始导入”，展示具体缺项弹窗及红色“（必填）”标记。
- 选择 Windows 解压目录中的 `gallery`，展示“已读取目录：gallery/”“40 人 · 120 张照片”，直接点击“开始导入”，不需要填写数据批次。
- 如现场再点击开始，已存在的 40 名同名人员会跳过。讲解为重复导入保护，不把“跳过”说成新增成功。不删除已有图库来制造演示效果。
- 说明每人照片需通过单人脸检查，失败人员会显示原因；正在导入时不能切换目录，处理结束后可再次选择。

## 收尾与常见提问

- “采用什么方法？”——后端使用 SCRFD 检测、五点对齐与 ArcFace 特征；归一化特征以余弦相似度匹配。增强提供 Gamma、CLAHE、Retinex、自适应等方法。
- “批量身份包能直接在实验页导入吗？”——不能。身份包用于注册参考照片；实验页需要包含 manifest.json、身份、人脸框、场景及会话标注的校准/测试 ZIP。
- “性能是不是已经达到 95%／90%／95%？”——当前有公开数据的真实研究结果，但对应实景证据仍不足，尚不能认定这三个目标都已验证。
- 建议结束语：“系统已形成增强、检测、身份注册、匹配及评估的完整流程，接下来需要补充独立真实场景数据完成目标验收。”
